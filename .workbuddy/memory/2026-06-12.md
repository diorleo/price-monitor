## 修复：Run Crawl 不包含用户自定义渠道 & 仪表盘渠道数不准确 (fab1fde)

**问题根因：**
- 用户通过 GitHub Pages 前端添加渠道 → POST 到 Render 后端 SQLite → 成功
- Render 免费版重启后 SQLite 被重置 → 自定义渠道丢失
- 前端 renderChannels 通过 localStorage 补齐显示，但后端 run_crawl 只查 DB（仅 7 个默认渠道）
- Dashboard 的 total_channels 也直接取 DB 数据（永远显示 7）

**修复方案（纯前端）：**
1. 新增 `syncChannelsToBackend()` — Run Crawl 前将 localStorage 渠道 POST 到后端，用后端返回的新 id 更新 localStorage
2. `renderDashboard()` 合并 localStorage 渠道计数，确保仪表盘显示准确

**改动文件：** `webapp/index.html` (+49/-1)
**待验证：** 等 Render 重建后，用户添加渠道 → Run Crawl → 应包含所有渠道

## 第二次修复：syncChannelsToBackend 彻底重写 (178afa1, 2026-06-16)

**根因深入分析：**
- `renderChannels()` 合并 API + localStorage 后，调用 `saveStore()` 把7个默认渠道也写入了 localStorage
- `syncChannelsToBackend()` 从 `loadStore()` 读数据时，发现每条渠道的 name 或 id 都能在 API 里匹配上（因为刚被 `renderChannels` 写回去了），于是全部 `continue` 跳过
- 结果：用户自定义渠道永远不会被 POST 到后端

**修复方案：**
1. `syncChannelsToBackend` 改为遍历 `DB.channels`（内存当前值），而非 `loadStore()`
2. 用 `DEFAULT_CHANNEL_NAMES` 集合（7个默认渠道名）过滤，只同步用户自定义渠道
3. 判断用 name 而非 id（id 在 Render 重启后会重新分配）
4. `renderChannels` 也改用 name 匹配；写回 localStorage 时只存用户自定义渠道（排除默认7个）
5. `renderDashboard` 渠道计数同步改为从 `DB.channels` 读取用户渠道数

**改动文件：** `webapp/index.html` (+49/-19)
**待验证：** Render 重建后，添加自定义渠道 → Run Crawl → 应包含所有渠道，且仪表盘计数正确
